Capítulo 0

Para quién es este marco

Este documento es un mapa mental compartido: las mismas ideas aplican aunque cambies de producto. Lo que cambia es la interfaz (dónde escribes) y el nombre comercial del modelo (GPT, Gemini, Claude, etc.).

Chatbots

ChatGPT, Gemini, Claude.ai — conversación en el navegador.

Asistentes en el editor

Copilot, Cursor, Gemini Code Assist — IA dentro del código.

Agentes

Sistemas que además de responder, usan herramientas y dan pasos.

Idea clave No memorices marcas. Memoriza el marco: modelo + instrucciones + contexto + herramientas + memoria.
Capítulo 1

Qué es un LLM

LLM significa Large Language Model (modelo grande de lenguaje). Es un programa entrenado para predecir y generar texto (y a veces código, imágenes o audio) de forma coherente, a partir de lo que le escribes.

Analogía: no es una base de datos que “busca la respuesta correcta”. Es más parecido a un asistente muy leído que completa lo que parece más probable según lo que ha visto en el entrenamiento y lo que le das ahora.

Un LLM no:

  • entiende el mundo como una persona (simula comprensión con patrones de lenguaje);
  • garantiza hechos al 100% (puede inventar con seguridad aparente);
  • recuerda automáticamente tu empresa o tu proyecto (salvo que se lo des o tenga memoria).

Un LLM sí:

  • explica, resume, traduce, redacta y propone código con rapidez;
  • sigue instrucciones si están claras;
  • mejora mucho cuando le das contexto bueno (archivos, reglas, ejemplos).
Capítulo 2

Qué es un modelo de LLM

El modelo es la versión concreta del cerebro estadístico: por ejemplo GPT-4.1, Claude Sonnet, Gemini 2.5, Llama 3, etc. La aplicación (Cursor, Copilot, Gemini) es la caja que lo usa.

ConceptoEjemploQué es
Proveedor OpenAI, Google, Anthropic, Meta Quién entrena y hospeda el modelo
Modelo GPT, Gemini, Claude, Llama El “cerebro” con pesos fijos
Producto / IDE Cursor, Copilot, Gemini en Chrome La herramienta donde lo usas
Agente Agent mode, Auto, Assistants Modelo + herramientas + bucle de pasos
Importante Cambiar de modelo (más capaz / más barato / más rápido) cambia la calidad. El marco (AGENTS.md, memoria, buenas preguntas) sigue siendo el mismo.
Capítulo 3

Cómo “aprende” la IA

En el día a día, el modelo que usas no está estudiando tu conversación para reentrenarse al instante como un alumno. Hay tres capas distintas:

1. Entrenamiento (antes de que tú lo uses)

Con millones de textos e instrucciones, los ingenieros ajustan miles de millones de parámetros numéricos (“pesos”). Eso define el conocimiento general del modelo. Ese paso es costoso y ocurre fuera de tu chat.

2. Contexto de la conversación (lo que ve ahora)

Todo lo que le escribes, los archivos que le adjuntas y las reglas del proyecto entran en una ventana de contexto (memoria de corto plazo limitada). Ahí “aprende” tu caso… pero solo mientras quepa en esa ventana.

3. Memoria / archivos del proyecto (lo que tú persistís)

Si guardas convenciones en AGENTS.md, memory.md, rules o skills, el agente las puede volver a cargar en sesiones futuras. Esa es la forma práctica de que “recuerde” cómo trabaja tu equipo.

Analogía escolar: el entrenamiento es la carrera universitaria; el chat es el examen abierto con los apuntes que le pasas hoy; AGENTS.md / memory.md son la carpeta de apuntes del equipo que se reabre cada clase.
Capítulo 4

Por qué no da las mismas respuestas

Si haces la misma pregunta dos veces, a menudo obtienes respuestas distintas. No es un fallo raro: es cómo funcionan estos sistemas.

CausaExplicación sencilla
Aleatoriedad (temperatura) El modelo elige entre varias palabras “buenas”, no siempre la misma.
Contexto distinto Otro historial, otros archivos abiertos, otras reglas cargadas.
Modelo distinto Cambiar de GPT a Gemini o de “rápido” a “pensante” cambia el estilo.
Ambigüedad de la pregunta Si no especificas, el modelo asume; cada vez puede asumir distinto.
Herramientas Si busca en la web o en el repo, los resultados pueden variar.
Cómo estabilizar respuestas Sé específico · da ejemplos · fija reglas en AGENTS.md · pide formato concreto · divide el problema · verifica hechos críticos tú o con tests.
Capítulo 5

Qué es un IDE de trabajo con IA

Un IDE (Integrated Development Environment) es el entorno donde escribes código: editor, terminal, git, depurador… Un IDE con IA añade el modelo (o un agente) dentro de ese entorno.

Chat solo

Hablas con la IA; tú copias y pegas el resultado al proyecto.

IDE / agente

La IA lee archivos, edita, ejecuta comandos y propone cambios en el repo.

Ejemplos (todos encajan en este marco):

  • Cursor — editor + agente con tools y rules/skills.
  • GitHub Copilot — autocompletado y chat/agente en VS Code u otros.
  • Gemini — chat y asistentes de código en productos Google.
  • Otros — Windsurf, Continue, Claude Code, etc.
Para el principiante Empieza preguntando en lenguaje natural (“explica este archivo”). Luego pide cambios pequeños. Después añade AGENTS.md para que no repita errores.
Capítulo 6

Qué es un agente

Un agente es un LLM al que se le permite hacer cosas en bucle: pensar ? usar una herramienta ? ver el resultado ? decidir el siguiente paso ? … hasta completar (o fallar) la tarea.

Herramientas típicas:

  • leer / editar archivos;
  • buscar en el código;
  • ejecutar terminal o tests;
  • consultar APIs o sistemas externos (a veces vía MCP u otras integraciones).
Analogía: el chatbot es un consultor que habla. El agente es un pasante al que le das acceso al repo y le pides que haga el PR (con supervisión tuya).
Seguridad Un agente puede borrar archivos o ejecutar comandos. Empieza con tareas pequeñas, revisa los cambios y no le des secretos en el chat.
Capítulo 7

AGENTS.md

AGENTS.md (o archivos equivalentes: rules, instrucciones del proyecto, system prompt del bot) es un manual corto del proyecto para el agente. Vive en el repositorio y se versiona con Git. Cualquier persona o herramienta compatible puede leerlo.

Qué poner (y qué no):

Sí

Cómo construir/testear · estilo del repo · arquitectura · qué no tocar · enlaces a ejemplos canónicos.

No

Manuales enormes · secretos · toda la wiki · reglas que solo aplican una vez (eso va a un skill o a un prompt puntual). 

# AGENTS.md — ejemplo mínimo

## Comandos
- Instalar: npm install
- Test: npm test
- Build: npm run build

## Estilo
- TypeScript estricto
- Preferir funciones pequeñas y nombres claros

## Arquitectura
- UI en /src/ui
- Lógica de negocio en /src/domain
- No editar /generated

## Preferencias
- Responder en español
- Explicar cambios brevemente al final

En algunos productos se llaman “Project instructions”, “Custom instructions”, “Rules” o “.github/copilot-instructions.md”. La idea es la misma: contexto always-on del equipo.

Anidamiento Puedes tener un AGENTS.md global y otros en subcarpetas (frontend/, backend/). Lo más específico suele ganar cuando trabajas en esa zona.
Capítulo 8

memory.md — memoria del agente

Si AGENTS.md es el manual del proyecto, memory.md (o “Memory”, “notas de sesión”, “hechos recordados”) es el cuaderno vivo: decisiones, preferencias y hallazgos que deben sobrevivir entre conversaciones.

AGENTS.mdmemory.md
Naturaleza Estable, de equipo Evolutiva, de trabajo
Contenido Cómo se trabaja aquí Qué ya decidimos / aprendimos
Cambia Poco (PRs conscientes) A menudo (notas cortas)
Ejemplo “Usamos Vitest, no Jest” “El bug de login es por el timeout del API X”

En la práctica No todas las herramientas usan el nombre memory.md. Algunas tienen “Memory” en la UI, otras un archivo en el repo, otras un almacén clave-valor del host. El principio es idéntico: persistir lo que no debe olvidarse.
Higiene de memoria No guardes secretos ni datos personales. Borra notas obsoletas. Si la memoria crece demasiado, resume y archiva.
Capítulo 9

Piezas del marco de referencia

Independiente del producto, un sistema serio de trabajo con agentes suele tener estas capas:

CapaPregunta que respondeEjemplos de nombre
Modelo ¿Qué cerebro uso? GPT, Gemini, Claude, Llama
Instrucciones estáticas ¿Cómo trabajamos siempre? AGENTS.md, rules, custom instructions
Memoria ¿Qué ya sabemos / decidimos? memory.md, Memory UI, kv del host
Procedimientos ¿Cómo se hace X cuando hace falta? skills, prompts guardados, playbooks
Herramientas ¿Qué puede hacer además de hablar? editar archivos, terminal, MCP, APIs
Conocimiento externo ¿De dónde saca hechos del negocio? RAG, búsqueda, docs, tickets
Control ¿Qué está permitido? hooks, permisos, revisión humana
Piensa en onboarding de un compañero nuevo: AGENTS.md = manual del día 1 · memory.md = notas del equipo · skills = “cómo desplegar” · tools = laptop y accesos · RAG = biblioteca · hooks = políticas de seguridad.
Capítulo 10

Primeros pasos prácticos

  1. Elige una herramienta (chat o IDE) y un modelo “equilibrado”.
  2. Haz una pregunta simple sobre un archivo tuyo: “explícame qué hace”.
  3. Pide un cambio pequeño y revísalo línea por línea.
  4. Crea AGENTS.md con 15–40 líneas: comandos, estilo, lo que no debe tocar.
  5. Crea memory.md (o activa Memory) y anota 3 decisiones reales.
  6. Repite una tarea (por ejemplo “abre un PR”) y conviértela en skill/prompt guardado.
  7. Mide: si el agente falla igual 3 veces, añade una regla; no alargues el chat eterno.
Prompt de principiante que funciona “Contexto: … Objetivo: … Restricciones: … Formato de salida: … No inventes archivos que no existan.”
