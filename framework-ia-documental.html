Paso 0

Mapa del framework

Un agente de IA no es solo un modelo: combina instrucciones, recuperación de conocimiento, tools y controles de seguridad. Cursor organiza esas capas en cada turno.

EstáticoRules + AGENTS.md
DinámicoSkills + RAG + MCP
ControlHooks + Subagentes
Analogía de onboarding Rules / AGENTS.md = día 1. Skills = manuales bajo demanda. Hooks = políticas. MCP = sistemas externos.

Flujo: Usuario ? Agente (+ rules) ? Skills ? RAG/vectores ? MCP ? Hooks ? Respuesta o acción.

Paso 1

El problema del contexto

El LLM no conoce tu negocio ni datos privados, y la ventana de tokens es finita: no cabe todo el conocimiento en cada prompt.

LímiteMitigación
Entrenamiento desactualizadoRAG + docs vivos
Datos privadosIndexación / MCP
Ventana de tokensRecuperación + skills
Convenciones del equipoRules / AGENTS.md
Regla de oro Separa siempre-on (rules) de bajo demanda (skills, RAG, MCP). Ahorra tokens y reduce ruido.
Paso 2

RAG (Retrieval Augmented Generation)

RAG recupera pasajes relevantes de un corpus externo y los inyecta en el prompt antes de generar. Así el modelo responde con evidencia, no solo con memoria de entrenamiento.

PasoDetalle
IndexarDocumentos ? chunks ? embeddings
ConsultarLa pregunta se convierte en vector
RecuperarTop-K vecinos por similitud
AumentarChunks + prompt al LLM
GenerarRespuesta anclada a evidencia

RAG fijo

Pipeline fijo. Ideal para Q&A sobre un corpus estable.

RAG agentic

El agente decide cuándo/cómo buscar e itera. Ideal multi-paso.

Paso 3

Base vectorial

Guarda embeddings (vectores numéricos) y busca por similitud semántica, no por keyword exacto.

Chunking

Partir documentos con tamaño y solape adecuados.

Embedding

Texto ? vector; significados cercanos quedan cerca.

Índice ANN

HNSW: vecinos aproximados a escala con baja latencia.

Ejemplos: Pinecone, Qdrant, Weaviate, Chroma, pgvector, FAISS, OpenSearch k-NN.

Paso 4

AGENTS.md

Markdown en la raíz o subdirectorios con instrucciones del proyecto. Anidable: las más específicas tienen prioridad. 

# Project Instructions

- TypeScript

- Repository pattern
Cuándo usarlo Ideal para instrucciones claras sin el overhead de rules con frontmatter.
Paso 5

Rules

Archivos en .cursor/rules/: contexto always-on. Cortas, con punteros a ejemplos, comandos de build/test y guardrails.

Costo de contexto Si solo aplica a veces, usa un skill. No copies style guides enteros (usa linter).
Paso 6

Paquete portable con SKILL.md (+ scripts/references). Se carga bajo demanda o se invoca con /.

Paso 7

Hooks y subagentes

Hooks: scripts en el ciclo de vida (observar o bloquear) — formatters, secretos, gates de shell/SQL. Subagentes: contexto aislado para exploración, revisión o verificación.

PiezaRol
Hooks AgentpreToolUse, beforeShellExecution, stop
Hooks TabbeforeTabFileRead, afterTabFileEdit
SubagentesDelegación con contexto propio
BDK bot/hooks/*.ts son observe-only. Las decisiones viven en tools.
Paso 8

MCP (Model Context Protocol)

Conecta tools y datos externos (Slack, Datadog, Sentry, bases de datos, Figma). También puedes usar CLIs (gh, aws, kubectl) documentados en rules.

RAG + MCP RAG = corpus indexado. MCP = sistemas vivos. Un agente maduro usa ambos.
Paso 9

BDK (Bot Development Kit)

Agentes como código: Markdown + TypeScript + evals en bot/, con deploy managed o self-hosted. 

bot/: agent.ts, instructions.md, tools/, skills/, hooks/, channels/
evals/
OpciónCuándo
AutomationsJob con prompt + trigger
Agent UIInteractivo sin proyecto de software
BDKCódigo, tests y deploy propios

Invariantes: Node (no Bun), memoria durable en ctx.host.kv.

1 AGENTS.md · 2 Rules cortas · 3 Skills · 4 MCP · 5 RAG/vectores · 6 Hooks · 7 BDK
